# 文件识别及解析规则

本文中的偏移均从文件起点开始，整数按 little-endian 解释。二进制布局是对有限样本的观察，不是厂商规范。

## `.mbs`：Modbus Slave

### 7.x 二进制格式

- 偏移 `0x00`：观察值 `7300`（`uint32`）。
- 已检查程序：Modbus Slave 7.3.0 Build 1402。
- 样本中后续区域包含功能码、起始地址、数量、站号、单元格及布局状态。

### 10.x 二进制格式

- 偏移 `0x00`：观察值 `10000`（`uint32`）。
- 其后可观察到 MFC 风格 Unicode CString，样本内容为 `10.0.0.2493`。
- 已检查程序：Modbus Slave 10.0.0 Build 2493。
- 新旧布局不能通过替换开头版本整数互相转换。

## `.mbp`：Modbus Poll

### 6.4.2 二进制格式

- 偏移 `0x00`：`6402`（`uint32`）。
- 在已检查样本中观察到：
  - `0x08`：起始地址；
  - `0x0C`：功能码；
  - `0x10`：读取数量；
  - `0x14`：扫描周期（毫秒）；
  - `0x18`：从站地址；
  - `0x160`：表格列数；
  - `0x164`：表格行数。
- 单元格区域的计算方式在已检查样本中为：

  ```text
  cell_start = 0x168 + 4 * column_count + 4 * row_count
  ```

这些偏移只应用于签名为 `6402` 且通过完整边界检查的文件。

### MFC CString 注意事项

旧二进制样本使用 MFC `CArchive` 风格字符串：

- 空字符串也占用一个长度字节：`00`；
- 已观察到的短 Unicode 字符串以 `FF FE FF` 开始，随后是单字节字符数和 UTF-16LE 数据；
- 不得把空字符串序列化为“零字节”。这样会让后续单元格与页尾数据错位，并导致 Modbus Poll 报 `Unexpected file format`；
- 长字符串可能使用不同的扩展长度编码，本研究未验证，不应猜测实现。

### 13.2.1 XML 格式

已检查样本具有以下开头：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<ModbusPoll>
  <FileSchema ... />
  <Version major="13" minor="2" patch="1" build="2558" />
  <!-- 其他元素 -->
</ModbusPoll>
```

已观察到的一级元素包括窗口位置、扫描周期、从站地址、显示参数、日志设置以及 `Data`。解析器应忽略未知元素并保留其内容，以便未来版本扩展。

## 推荐的识别顺序

1. 检查扩展名，但不把扩展名作为可信格式证明。
2. 限制允许读取的最大文件大小。
3. 如果去除 UTF-8 BOM 后以 XML 声明或 `<ModbusPoll` 开始，使用安全 XML 解析器并核对根节点和 `Version`。
4. 否则至少读取 4 字节 little-endian 整数：
   - `.mbp`: `6402`；
   - `.mbs`: `7300` 或 `10000`。
5. 对所有数量、偏移、字符串长度和乘法执行溢出及文件边界检查。
6. 未识别格式必须拒绝，不能尝试“尽量解析”。
