# 安全实现建议

## 解析器设计

- 为每个已识别代际使用独立后端：`mbs_v7`、`mbs_v10`、`mbp_v6`、`mbp_v13_xml`。
- 先识别格式，再解析；不要用异常作为正常的版本探测流程。
- 输出统一领域模型，但保留来源版本、原始地址、功能码、数据宽度和未知字段。
- 默认只读。写回二进制格式应当是单独功能，并要求显式备份。
- 文件损坏、截断、计数越界和重叠字段必须返回结构化错误，不能让 UI 崩溃。

## 二进制写回

没有完整规范时，优先级依次为：

1. 使用原软件提供的正式保存接口；
2. 保留未知字节，只对已确认字段进行原位、等长修改；
3. 经真实软件打开并重新保存后做字节差分；
4. 最后才考虑完整重建。

不要用读取器自己的反向逻辑作为唯一验证，因为同一个错误可能同时存在于生成器和校验器中。至少应增加：

- 独立解析器验证；
- 真实目标版本打开测试；
- 重新保存后的语义对比；
- 截断、超长字符串、非法计数和随机数据测试。

## XML 安全

- 禁用 DTD 和外部实体；
- 设置文件大小、节点深度、节点数量和文本长度上限；
- 只接受 `ModbusPoll` 根节点；
- 不执行文件中的路径、命令、宏或外部引用；
- 保留未知元素以支持前向兼容。

## 地址显示

工程文件中的起始地址通常是协议数据地址。界面中的 `4xxxx`、`3xxxx` 等引用表示法以及“一基址显示”是显示层概念。解析器应分别保存：

- 原始零基地址；
- 功能码；
- 用户界面的显示模式。

不要把 `40001` 直接当作 PDU 地址发送。

## 测试数据

公开仓库应使用人工生成、去业务化的最小夹具。不要提交客户工程、真实设备名称、串口设置、IP 地址、寄存器中文名称或厂商程序文件。
